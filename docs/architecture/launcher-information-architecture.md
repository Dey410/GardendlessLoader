# 启动器功能与信息架构

日期：2026-10-14。范围：重排UI并补齐原有功能，尚未连接新的生产界面。基准为当前生产`home_page.dart`、`AppController`、README与原生桥，不能以此前视觉预览的精简内容代替产品需求。

## 设计依据

按用户指定读取并采用Emil Kowalski的[apple-design](https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md)和[emil-design-eng](https://github.com/emilkowalski/skills/blob/main/skills/emil-design-eng/SKILL.md)。两者主要用于Web设计与交互；Flutter实现需要映射到平台行为，不机械搬入Web库。

本次采用的规则：按任务分组，控制靠近所影响的内容；常用路径清晰，高级信息下一层；同一作用域的同一动作只有一个主要入口；简单不意味着删除功能。导航切换立即响应，按钮按下立即反馈，偶发面板转场约150–250ms。键盘导航不播放装饰转场；减少动效、减少透明度、高对比分别处理。

真实布局参考：

- [Apple iPad Tab Bar与Sidebar](https://developer.apple.com/documentation/uikit/elevating-your-ipad-app-with-a-tab-bar-and-sidebar)：并列功能快速切换与较深层级导航是两种不同需求，不能只为了“像苹果”同时叠加两套导航。
- [UTM官方单VM详情](https://github.com/utmapp/UTM/blob/main/Platform/Shared/VMDetailsView.swift)：一个当前对象、一个运行主动作、状态与明细。适合单游戏加载器，应用VM库和硬件参数不属于本项目。
- [Apple Files视图与预览](https://support.apple.com/en-euro/guide/ipad/ipad49b77901/ipados)：选择对象、查看信息与执行动作分开组织。用于资源/日志页面，不把整个文件管理器搬成游戏首页。

## 对上一稿的评审

| Before | After | Why |
| --- | --- | --- |
| 顶部导入、游戏资源行、资源Sheet都引向同一操作 | 资源页有唯一ZIP导入/更新动作；游戏页只启动 | 同一页不重复布置同一任务 |
| 水印、音频诊断在不同Sheet重复出现 | 游戏偏好只在游戏页，音频诊断只在日志页 | 用户可以预测设置在哪里 |
| 大封面、Logo、缩略图、重复标题占据大量空间 | 单组游戏身份和紧凑预览，空间留给状态与动作 | 这是本地工具的运行页面，不是宣传页 |
| 更新流程缺失，仅有示例说明 | 应用和游戏各自保留版本、来源、暂缓和比较结果 | 视觉精简不能删除原有能力 |
| 日志压缩成一个小Sheet中的示例错误 | 日志成为完整页面，保留筛选、事件、复制与历史管理 | 密集信息需要稳定空间与独立操作层级 |
| 固定时长弹跳/模糊被用来表达“苹果感” | 高频导航即时、少量操作反馈、可中断的面板过渡 | 动效服务操作，不阻挡操作 |

## 四个目的地与唯一归属

| 目的地 | 用户任务 | 唯一主要动作 |
| --- | --- | --- |
| 游戏 | 玩当前游戏，设置下一次启动的偏好，阅读公告 | 开始游戏 |
| 资源 | 导入/更新资源，查看当前资源信息和游戏版本 | 选择ZIP导入/更新 |
| 日志 | 排查故障、读取和复制日志、控制音频采集 | 刷新、复制诊断、历史日志管理，各有独立用途 |
| 设置 | 加载器版本/更新、应用外观、关于与使用说明 | 加载器更新与应用级偏好 |

“检查更新”是一个全局命令，同时检查应用和游戏，物理控件只出现一次。只读版本显示不再同时充当第二个检查按钮。应用与游戏的获取来源分别留在其上下文，标签说明对象；它们当前共用网盘配置不意味着可混淆两个更新任务。

自动收集写入资源manifest；详细音频诊断和水印写入app_settings。音频采集只在日志页修改。水印若在新UI暴露，属于既有后端能力的新可见入口，唯一放在游戏偏好。JS Modding始终由游戏内GP-Next管理。

## 两种布局参考

### 顶部标签

平板顶部四个同级目的地，手机转底部四项。当前页面拥有自己的工具和主动作。适合频繁在资源、日志之间切换；首页不会再次铺四张相同去向的入口卡。

### 侧栏工作区

宽屏使用Apple式稳定侧栏和单一内容区域，手机同样转底部四项。适合iPad上持续看日志、展开资源详情。侧栏不会同时再出现顶部四标签或底部重复导航。

两种方案使用相同功能与状态，不通过删掉功能制造“更简洁”的假比较。布局参考用示例数据演示本地状态、页面与确认流程，不连接真实文件、日志或更新服务。正式原生选择器、Clipboard、存档和GPNext行为由生产实现接入。

## 评审规则

1. 对每个可见动作记录唯一owner，不允许同页重复导入/检查/修改同一偏好。
2. 对完整矩阵逐项标记入口和状态，不能把“有一个按钮”当成已有完整行为。
3. 对照无资源、旧资源、更新失败、取消、版本未知/领先、无日志/日志降级、长路径和大字体。
4. 高频导航即时；按钮在按下时反馈；偶发确认和面板淡入保持短且可中断。
5. 外部skills用于设计约束，源码、状态和真机测试用于验证，不能用skill名称代替验证。

## 本轮布局验证

2026-10-14，在本机实际浏览器检查交互参考。当前文件为线程内的`gardendless-layout-study.html`，104718字节；脚本语法检查通过，不含网络API调用。它使用明确标注的示例数据，未连接真实资源、日志、原生选择器或游戏。

- 顶部标签方案在320宽度下逐一检查游戏、资源、日志、设置：无横向溢出、控件未越界，所有可见按钮高度至少44像素。手机侧栏候选也重排为单个底部导航，无重复导航。
- 在1024平板宽度检查两种布局，资源页宽度与scrollWidth一致；1280宽度检查设置页面。原型仅证明这些检查点，不代表已验证所有设备、大字体或读屏行为。
- 实际走通示例ZIP选择、导入成功与取消。进度更新和完成后保留展开的导入详情；资源根目录显示与复制内容一致，导入与全局检查各只有一个物理入口。
- 导入期间同时检查更新，再取消导入，检查仍完成。取消按钮消失后焦点回到“关闭提示”；检查期间打开目录复制面板，关闭后焦点回到当前页面的复制按钮。
- 开启“只看错误”后事件列表只有错误，而完整诊断仍含4条近期事件及INFO/WARN；确认清理内存示例历史后保留当前会话3条事件。没有删除设备文件。
- 控件语义、模态标题、同值状态回显、独立计时器、导入成功重置自动收集及空公告/失败分支经过独立代码审查。场景控制提供12种状态供探索，未宣称每个状态组合都已做浏览器或真机验收。
- 最后两轮浏览器未记录到脚本error/warn。源文件、功能矩阵与焦点恢复修改经独立复核，未发现新的实质问题。
