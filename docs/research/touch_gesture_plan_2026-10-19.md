# 触屏手势完整计划

日期：2026-10-19。分支：`compat/gardendless-0.15-and-later`（基于 `6ffe5ae`）。
状态：已实现，作为设置里的实验选项“手势（实验）”交付：**模拟**为默认值，保留 ADR-0002 的旧方案；**原生**即本计划。W1–W5 和第 11 节"不需要两根手指"已实现并通过自动检查，W6、W7 按选项调整后完成，均未提交、未经真机验证。决定记录见 ADR-0003。

> 实施说明：原生方案的全部行为都受会话字段 `touchGestureMode`（`simulated` / `native`）控制。该字段从 Dart 设置经 `GameSession` 和三端原生宿主，写入 `__gardendlessHostConfig.touchGestureMode`。在模拟模式下，适配器和状态机的行为与已提交版本一致，已提交的检查脚本对新代码全部通过；`game_drag.js` 也不会安装任何钩子。

研究所用的游戏包都是 PvZGE 0.15.0、Cocos 3.8.4：`GardendlessResources.zip`（producer `73c4989`）和 `pvzge-lite-0.15.0-loader-0.9/package/GardendlessResources-0.15.zip`（producer `c9f4d89`）。两者的游戏脚本行为一致。文中凡是没有在真机上确认的结论，都标为**待验证**。

## 0. 结论

旧方案对触屏只做一件事：把手指翻译成鼠标，再补上游戏缺的操作。它带来三个问题：

- 为了让拖动能种植，在松手点补一次点击。这次点击会打断列表的惯性，还会误选手指下的条目。
- 滚轮和右键都只能靠双指模拟。
- 有些右键操作在触屏上做不了。

新方案按"手机玩家期望这个手势做什么"来设计，并把每种含义放在真正理解它的那一层：

- **通用手势**（点、拖、双指点、滑、捏）放在共享触摸状态机和适配器里，不依赖游戏知识。
- **游戏含义**（拖放种植、拖空自动放回、禅境花园平移）放在游戏钩子 `game_drag.js` 里。钩子复用游戏自己的代码路径，不合成额外事件。
- **右键**只保留给少数只有右键才能完成的次要操作，手势仍是双指轻点。最常用的"放下手上的东西"改由拖放和"再点一次"完成。

## 1. 游戏怎么读输入（代码证据）

### 1.1 左键：按下就生效

- 卡片节点的 `MOUSE_DOWN` 调用 `UI.tryChangingIndex(n)` 拿起卡片。`UIInGame.index` 的取值：0–7 为种子卡，8 为传送带卡，9 为沙盒僵尸卡，-2 为铲子，-3 为肥料。
- 再次选择同一个 index 时，`tryChangingIndex` 会把它放下（变为 -1）。卡片、传送带、沙盒僵尸卡、铲子、肥料都是这样。
- 种植链路：`UI.onMouseDown` → `Mouse.mouseInLnC.onMouseDown(e, true)` → `LnC.PlaceUIPlant()`。最后一步负责扣阳光、开始冷却、推进教程和清空手牌。
- `LnC.onMouseUp` 只处理矿车，松手从来不会种植。
- `Mouse.mouseInLnC` 由 `Square.update` 在下一帧根据 `Mouse.position` 推导，`Mouse.position` 则在每次 `MOUSE_MOVE` 时同步更新。`Square.update` 带有枯萎植物层销毁、电线、矿车移动等副作用，所以不能在帧外调用。
- `UI.onMouseDown` 和 `UI.onMouseUp` 都有 `MouseClickCoolingDown` 防抖：每次处理后设为 2，每个 `lateUpdate` 减 1。

### 1.2 鼠标与触摸

- Cocos 3.8.4 在网页端把左键的按下、移动、松开模拟成 touch id 0（`input._simulateEventTouch`）。因此标准 `cc.ScrollView`、世界地图的 `TOUCH_MOVE` 等触摸逻辑，用鼠标拖动也能驱动。
- `ScrollView._onTouchMoved`：移动超过 7 单位后，给子节点发 `TOUCH_CANCEL`。
- `ScrollView._onTouchBegan`：调用 `_handlePressLogic`，立即停止惯性滚动。
- 图鉴、选卡器、玩家列表等列表条目在 `TOUCH_END` 时选中。
- 设置窗口使用 `ScrollViewWithoutTouchevent`，四个触摸回调都被覆盖为空，是作者有意关闭了触摸滚动，因为窗口里有音量和速度滑块。

### 1.3 滚轮

- 引擎：`getScrollY() = 5 × (−deltaY)`；`ScrollView` 竖直方向的内容位移为 `−0.1 × scrollY`。
- 关卡内的 `UI.onMouseScroll` 每个游戏帧最多接收一次（设置 `MouseClickCoolingDown = 1`），每次只走 ±1 格，不看滚动幅度。
- 滚轮的用途：

| 场景 | 滚轮含义 |
|---|---|
| 标准 ScrollView 列表 | 连续滚动 |
| 设置窗口 | 连续滚动（触摸滚动被游戏关闭） |
| 沙盒：切换植物卡、僵尸卡、僵尸护甲；草坪上推矿车、切换装扮 | 每个事件走 ±1 格 |
| 世界选择 | 每个事件左右切换 ±1 |
| 世界地图 | 连续平移（同时支持 `TOUCH_MOVE` 拖动） |
| 禅境花园 | 缩放：`scale *= 1.01^(scrollY / 50)` |

### 1.4 右键

| 场景 | 右键作用 | 单指替代 |
|---|---|---|
| 关卡、卡片、传送带、沙盒僵尸卡、宝石迷阵种子 | 放下手上的东西 | 再点一次同一项（游戏本身就会切换） |
| 自定义卡组 | 打开编辑器 | 无 |
| 沙盒：右键植物 | 把卡槽切到该植物（吸管） | 无 |
| 空袭模式，空手 | 切换"飞行器跟随鼠标" | 无 |
| 解码小游戏 | 清空格子、放下卡片 | 部分 |
| 阳光作弊 | −1000 | 无 |
| 植物，空手 | 浇水动画（纯表现） | 不需要 |
| 禅境花园 | 按下时取消工具，按住拖动则平移（中键也能平移） | 无 |

中键点在植物上会直接使用肥料。肥料槽加点按或拖动已能覆盖这一功能。

### 1.5 帧率

- 游戏设置里的"动画帧率"可选不限（默认）、24、30、60。
- Cocos 的 Pacer 通过跳过 rAF 来实现目标帧率。因此用浏览器帧数计算的等待，无法保证游戏已经运行了一次 update。

## 2. 旧方案的问题

| 问题 | 原因 |
|---|---|
| 单指拖列表没有惯性，松手还会误选条目 | 拖动超过 20 物理像素后，在松手点等 2 帧加 50ms 再补一次按下和松开 |
| 补点击的时序依赖刷新率与游戏帧率之比 | 文档里只验证过 60 Hz WebView 配 30 Hz 游戏循环 |
| 沙盒切卡一滑就跳十几格 | 每个 `touchmove` 都发一个 wheel，而游戏每帧走 1 格 |
| 横向双指滑动松手会触发右键 | 状态机只看竖直位移 |
| 禅境花园无法平移 | 只能右键或中键拖动，而双指移动被当作滚轮 |
| 触屏上拿着东西没处放 | 看不到光标，只能靠双指右键放下 |

| 手势 | 效果 | 状态 |

| 单指点 | 左键点击 | 不变 |
| 单指拖（列表） | 引擎原生滚动，带惯性 | **已完成** |

### W2 拖了但没用上：自动放回

**规则**（只针对本次按下拿起的工具：0–8、-2、-3）：

1. 松手格是草坪格且不是拿起时所在的格：调用该格的 `onMouseDown(event, true)`。之后如果手上仍是同一个工具（例如格子已被占用），就调用 `tryChangingIndex(-1)` 放回。
2. 松手不在草坪上：如果 `Mouse.position` 离拿起时的位置超过阈值，就放回。没超过算点按，保持拿着。
3. 在拿起时所在的格上松手：算点按，保持拿着。

放回使用游戏自己的 `tryChangingIndex(-1)`，会播放游戏原有的取消音效。卡片、铲子、肥料都已验证会切换。

**阈值**：初始值 20 UI 单位，约等于 1024 设计宽度下的 20 CSS px，需要真机调整。

**检查**（`check_game_drag.mjs`）：

- 拖到被占用的格子 → 放回。
- 拖到草坪外 → 放回。
- 点卡片（不移动）→ 保持拿着。
- 在拿起的格上松手 → 保持拿着。
- 铲子拖到空格 → 放回。
- 游戏暂停时不放回。
- 右键松开不放回。

### W3 禅境花园单指平移

**做法**：

- 左键按下时，在游戏处理完这次按下之后（`setTimeout(0)`）再判断。如果此时 `zenGardenScene.component` 存在、节点有效，并且手上没有工具（`!isShoveling && !isGloving && !isCarting && !willMovePlantSlot`），就设 `component.pressed = true`，并记下这是我们打开的。
- 游戏自己的 `MOUSE_MOVE` 处理器在 `pressed` 时按 `getDelta()` 平移。
- 左键松开时，如果是我们打开的，就设回 `false`。下一次按下、`blur`、`visibilitychange` 时也清掉，避免下次按下前的定位移动造成画面跳动。
- 不取消工具；右键的"取消工具"在触屏上改为再点一次工具按钮（游戏本身就会切换）。

**判断时机**：在游戏处理完按下后再判断，这样按下的是工具按钮时，工具已经拿到手上，就不会平移。

**检查**：

- 空手按下 → `pressed`，松开后复位。
- 拿着铲子、手套或推车时不平移。
- 打断（blur 等）后复位。
- 不在禅境花园时不起作用。
- 接口缺失时记一次错误。

### W4 双指分类：点、滑、捏

**状态机规则**（`touch_state_machine.js`，不含游戏知识）：

- 第二根手指落下时，记录中心 `C0` 和两指间距 `D0`。
- 当 `|C − C0|`（二维）和 `|D − D0|` 都不超过 20 物理像素时，仍是点按候选。
- 任何一个超过阈值后，本手势锁定类型：
  - `|ΔD| > |ΔC|`：捏合；
  - 否则：滑动。
- 滑动：按每帧中心的竖直位移发 `scroll`，水平分量忽略。
- 捏合：按每帧间距的变化发 `scroll`，张开记为正，与"手指向下移"同号。在禅境花园里，张开就是放大。
- 松开时类型从未确定：在 `C0` 发右键。
- 与现状的差别：横向滑动也不再触发右键。

**检查**（`check_touch_state_machine.mjs`、`check_touch_patch.mjs`）：

- 竖滑 → scroll。
- 横滑 → 不发事件。
- 捏合张开、收拢 → scroll 的正负号正确。
- 小幅移动 → 右键。
- 类型一旦确定就不再改变。
- 三指 → 阻断。

### W5 滚轮刻度

**做法**（`touch_input_adapter.js`）：

- 继续沿用现有换算 `physicalDeltaY / dpr × touchWheelCssMultiplier`。三端都是 −4.5。
- 结果累加到余量里，每满 100 发一次 `deltaY = ±100` 的标准滚轮事件，和真实鼠标滚一格相同。
- 每个新的触摸手势开始时清空余量。

**效果**：

- 总滚动距离不变。按 −4.5 计算，约每 22 CSS px 滚一格，每格让 ScrollView 移动 50 个设计单位。
- 沙盒切卡等"每格一步"的操作，变成每 22 px 一步，而不是每个 `touchmove` 一步。

**调参**：真机上只调现有的 `touchWheelCssMultiplier`，不新增常量。若切卡仍太快，就减小它的绝对值，代价是设置页和禅境花园每滑同样距离滚得更少。

**检查**：

- 小于一格不发事件。
- 余量能跨帧累积。
- 正负方向都正确。
- 新手势会清空余量。

## 6. 不做的事与理由

| 方案 | 不做的理由 |
|---|---|
| 长按代替右键 | 游戏在按下时就选卡、使用卡组、种植。识别长按必须把每次左键按下推迟到手指移动或抬起，会改变所有点按的手感，还会破坏需要按住的交互 |
| 去掉按下前的两帧等待 | 点按种植依赖帧推导的 `mouseInLnC`。不调用带副作用的 `Square.update`、也不复制游戏逻辑，就无法去掉。保留等待，在 24/30 FPS 下做真机验证 |
| 中键映射 | 肥料槽加点按或拖动已覆盖 |
| 双指横向滚轮 | 横向列表单指就能拖；Cocos 横向 ScrollView 本来也读 `getScrollY` |

## 8. 风险与待调参数

- 游戏版本更新如果改了上表的成员名，对应手势会停用；点按种植不受影响。每次游戏版本升级时，用浏览器验证跑一遍。
- 鼠标和触控板玩家同样会得到拖放种植、拖空自动放回和禅境花园左键拖动平移。这是新增行为，旧操作不受影响。
- 在禅境花园以外的界面捏合，会像双指上下滑一样滚动。无害，但有些意外。
- 待调参数：`touchWheelCssMultiplier`（每格滚动的距离），以及 W2 的放回阈值。
- **待验证**：铲子拖动、空袭模式下"跟随鼠标"在触屏上的手感、24/30 FPS 下的点按种植。

## 11. 原生 = 不需要两根手指（追加）

第 5 节的版本仍有几处必须用两根手指。用户明确的目标是：原生模式像本来就是手机游戏一样，任何操作都不需要两根手指。逐项排查游戏代码后的处理如下。

| 原来需要两根手指的地方 | 现在的单指做法 | 实现 |
|---|---|---|
| 游戏内设置窗口滚动（`ScrollViewWithoutTouchevent` 关闭了触摸滚动） | 单指跟手滚动；从滑块开始的触摸仍交给滑块 | 替换该类原型上的四个触摸回调，起点在 `cc.Slider` 节点或其子节点上时不处理，其余调用基类 `cc.ScrollView` 的原方法 |
| 沙盒卡槽、沙盒僵尸卡片、僵尸护甲图标的滚轮切换 | 沿条带长边滑动即切换，每 40 CSS px 一格；朝草坪方向拖仍是拿卡种植 | 在条带内沿长边移动超过 16 CSS px 后进入切换，放回这次按下拿起的卡；在手指位置派发 `deltaY = ±100` 的滚轮事件，由游戏自己的滚轮处理器切换 |
| 编辑自定义卡组（只有右键） | 长按卡组 0.5 秒 | 向卡组节点发送右键 `cc.EventMouse`，由游戏自己的监听器打开编辑器 |
| 沙盒：把卡槽切到草坪上的某种植物（只有右键） | 空手长按植物 | 调用该格的 `plantMouseReact`，传入右键事件 |
| 解码小游戏清空格子（只有右键） | 长按已填的格子 | 向格子节点发送右键 `cc.EventMouse` |
| 禅境花园缩放 | 捏合 | 保留双指捏合，这是手机上的原生手势 |
| 沙盒设置页：大部分行只是键盘快捷键说明，只能用键盘或工具栏按钮关闭 | 点一行即关闭窗口并执行该快捷键；点窗口外关闭 | 先用 `showSBSettings()` 关闭窗口（窗口打开时游戏忽略沙盒按键），再把该行当前绑定的按键作为 `cc.EventKeyboard` 交给 `UIInGame.onKeyDown/onKeyUp`；点在窗口上方的按钮上时交给按钮本身 |

拖放也补到了其他"先点选、再点目标"的地方：沙盒僵尸卡、狙击类植物瞄准（拖到目标格松手即发射）、解码小游戏（把卡片拖到格子上，通过向格子发送左键 `cc.EventMouse` 由格子自己的处理器放置、合并或交换）、禅境花园手套（把植物拖到另一格，调用 `ZenGarden.MouseDown`），以及从工具按钮直接拖到格子上。没用上的拖动都会放回。

已经不需要双指的：放下手上的东西（再点一次同一项）、禅境花园取消工具（再点一次工具按钮）、空袭模式（关卡开始时游戏自动绑定鼠标，飞行器跟随手指）、世界选择（点两侧的世界即可切换）、矿车（直接拖动）。

长按只作用于上表三类目标，并直接调用该目标自己的右键处理，不合成 DOM 右键：引擎会把 DOM 右键同时转成触摸，从而再次按下手指下的按钮。长按卡组时，按下那一刻游戏已经使用了这个卡组；为避免这一点就得推迟所有卡组点按，所以接受这个副作用。

仍然只能用两根手指的有两项：作弊阳光计数器的 −1000（按下时游戏已先加了 1000），以及沙盒切换植物装扮（纯外观）。双指轻点和双指滑动在原生模式里继续可用，但帮助文字不再列出。

钩子文件更名为 `native_gestures.js`。每条规则单独检查自己依赖的游戏接口，缺失时记录一次"原生手势（规则）已停用"，其余规则照常工作。
