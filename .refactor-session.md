Protocol fixed before parallel work:

- `file:begin`: args `{mode: 'read'|'write', destination: 'gp-next'|'export', path?, options?, totalBytes?, suggestedFilename?, mimeType?}`. Returns `{handle, sizeBytes}`. Read is GP-only; export is write-only. Native validates its session capability and destination.
- `file:chunk`: args `{handle,index,offset,length? ,data?}`. Read returns `{data: base64}`; write returns null after writing. Exact order and byte count; maximum 65536 decoded bytes.
- `file:finish`: args `{handle,action:'close'|'commit'|'cancel'}`. Read close, write commit, either cancel. Commit export waits for picker result. Replies use the existing one final RPC response; no whole-file arrays or alternative transport.
- max file 512 MiB, max 8 handles, at most 2 active file IO operations with bounded queue; constants beside their real owner. All IO off UI callbacks; close/cancel remain admissible. Every handle belongs to one host session.
- GP high-level methods remain; shared JS converts binary reads into ArrayBuffer before the real Tauri wrapper, and chunks writes before serialization. Empty files/subviews preserve semantics. Existing export path from GP dialog/save still triggers native system saving when committed.
- Native config includes `hostAbi: 1` and explicit `platform`, plus the existing settings. Legacy Host exportBegin/Chunk/Commit/Abort and legacy GP whole/chunk writes are replaced, not kept as runtime fallbacks. `host:export` remains a URL-open operation.
